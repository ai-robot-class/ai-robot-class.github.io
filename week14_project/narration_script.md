# 第 14 周项目讲解 · 逐页配音脚本

> 配音由授课老师本人录音、用 voicebox 的 Chatterbox 多语种引擎克隆生成。

| 页 | 标题 | 配音文稿 |
|----|------|----------|
| 1 | 封面 | 同学们好，欢迎来到第十四周的项目课。这一周我们做一个小组项目：用你自己写的手机网页，通过 Tailscale 局域网，把控制指令送进电脑里的仿真程序，让机器狗或者小乌龟在迷宫里走起来。这一周不学新算法，而是把前面几周学过的网页、组网、仿真和控制，串成一条完整的工程链路。 |
| 2 | 控制链路 | 我们先看这条主线。手机网页是遥控器，负责发命令；命令通过 Tailscale 虚拟局域网传到电脑；电脑上有一个常驻的桥接程序，它一边接收网络命令，一边直接驱动机器人；最后机器人在迷宫里完成探索。整个项目以小组形式交付，包括代码、演示视频和报告书。 |
| 3 | 旧知识对应 | 这条链路的每一段，都对应着我们学过的内容。手机控制输入用到第十一周的网页部署；Tailscale 局域网是第十二周手机摄像头组网那一套；仿真程序来自第二、第八、第十三周的环境与仿真；机器人运动来自第十三周。本周的新要求是：前进、后退、左转、右转这四个动作都要能控制，并且在迷宫里完成探索。 |
| 4 | 选方向 | 选哪个方向，按小组人数来决定。三人及以上，建议做方向A机器狗，内容多、好分工；两人建议做方向B小乌龟，这是标准的 ROS2 链路；一个人也完全可以，做小乌龟即可。这里有一个重点要求：小乌龟项目，必须用算法让乌龟自动走出迷宫，不能只靠手动遥控；机器狗项目手动遥控就能达标，但如果小组达到四个人，同样要求实现自动探索迷宫。一句话：人多做机器狗，人少做小乌龟，单人也欢迎；小乌龟必做自动探索，机器狗满四人也要做。 |
| 5 | 单一程序原则 | 这是本周最重要、也最容易做错的工程概念。手机网页只负责发命令，不要在网页里写控制逻辑；网络接收和机器人控制，必须写在同一个常驻程序里。常见的错误，是再开第二个程序去接管同一条链路，结果状态混乱、命令丢失。记住：只要网页还在控制，桥接程序就不能关闭。 |
| 6 | Tailscale | 环境准备的第一步是 Tailscale。在校园网或机房里，手机直接访问电脑几乎一定失败，因为有接入点隔离和 WSL2 的网络隔离两道墙。Tailscale 给手机和电脑各分配一个一百点开头的虚拟地址，绕过这两道墙。推荐一人一网，手机和电脑登录同一个账号，最后用 tailscale ip 命令查到地址记下来。 |
| 7 | Docker环境 | 第二步，我强烈推荐用 Docker 一键准备环境。我们复用第十、第十一周用过的 ROS2 桌面镜像，它自带一个浏览器里的 Linux 桌面，turtlesim 和 PyBullet 的窗口都能在浏览器里看到。执行 docker compose up，打开 localhost 六零八零就是桌面，在里面跑一次 setup 脚本装好依赖就可以了。 |
| 8 | Docker端口 | Docker 的端口我们已经配好。六零八零是浏览器桌面，用电脑浏览器打开；八七六五是机器狗的控制器，八零八零是小乌龟的控制器，这两个用手机打开宿主机的 Tailscale 地址加端口来访问。注意，Tailscale 装在宿主机上，容器把端口映射到宿主机，所以手机连宿主机的地址就行。 |
| 9 | 方向A | 下面看方向A，PyBullet 机器狗迷宫。它是三维物理仿真，迷宫是算法生成的完美迷宫，机器狗撞墙会被真正挡住，走到终点会判定为到达。 |
| 10 | 迷宫总览 | 这是初始环境，一个十三米见方的完美迷宫。它用递归回溯算法生成，左下角橙色是起点，右上角绿色是终点。和旧版只有几道隔墙相比，这个迷宫有走廊、有死路，机器狗需要真正地找路，才能走到终点。 |
| 11 | 俯视图 | 这是俯视图，可以清楚看到迷宫的走廊和死胡同，橙色是起点、绿色是终点。手机网页上也有一个同款的实时俯视图，会画出机器狗走过的轨迹，方便你观察它在哪里、撞没撞墙。 |
| 12 | 代码结构 | 方向A的起始代码分成四个文件：server 是常驻程序，管仿真、网络和碰撞终点判定；maze 管迷宫生成；explorer 是自动探索骨架；index 是手机遥控器。核心在 step 函数里：先转向，再尝试前进，如果下一步会撞墙就保持原位并标记 blocked，走进终点圈就标记到达。 |
| 13 | 方向B | 再看方向B，turtlesim 小乌龟迷宫。它是标准的 ROS2 链路，迷宫是一个四乘四单元的完美迷宫，桥接程序已经帮你内置了碰撞规则。这里再强调一次：小乌龟项目要求你用算法让乌龟自动走出这个迷宫。 |
| 14 | 完美迷宫 | 这是方向B的初始环境，一个四乘四单元的完美迷宫，用递归回溯算法生成，并且我已经用广度优先搜索验证过，从起点到终点一定有解，图里的红色虚线就是其中一条可行的通关路线。走廊大约两个单位宽，乌龟有充足的通行空间，迷宫里有死路也有分叉，非常适合用沿墙走的算法来求解。绿色是起点，橙色是终点。迷宫的边界、障碍、起点和终点，都写在桥接程序的 OBSTACLES 列表里。 |
| 15 | 内置规则 | 方向B的桥接程序已经帮你做了不少安全工作：把手机命令发布成 ROS2 速度指令、订阅乌龟的位置、预测下一步会不会撞墙、会撞就把前进速度设为零、进入终点就判定到达，还能一键复位回起点。所以你可以把精力放在遥控和探索上。 |
| 16 | 遥控器网页 | 自己实现一个遥控器网页，是本周的统一要求之一。三个要点：方向键长按持续控制、松开就发停止；用 WebSocket 发送结构化的 JSON 命令；把回传的遥测显示出来，方便调试。起始的 index 网页可以直接用，也可以在它的基础上美化。 |
| 17 | 改代码 | 接下来讲最关键的部分：完成这个项目，到底要写或者改哪几个文件。记住，这个项目不是从零写，而是在起始代码上填空和扩展。 |
| 18 | 要动哪些文件 | 以方向A为例。maze 文件不改也能跑，想换更大更难的迷宫，就改 COLS、ROWS、SEED 这三个参数；index 网页可以美化或加自动手动切换；explorer 是核心加分点，去完善里面的探索算法；server 不改也能跑，进阶就是把 explorer 接进去，加一个自动模式。真正要写的代码不多，重点是理解每个文件的职责。 |
| 19 | 四步走 | 整个项目按四步走。第一步，先把链路跑通，四个方向键能用、撞墙能被挡住；第二步，改地图，只动一个文件；第三步，做自动探索，可以自己写算法、理解 explorer 巡墙器，也可以接入智能 Agent；第四步，做成果展示，画出轨迹、统计用时、录一段完整的视频。对小乌龟，自动探索是必做的；机器狗满四人也必须做，其余情况算加分。 |
| 20 | 接入自动模式 | 怎么把自动探索接进主程序呢？很简单。explorer 里已经给了一个右手法则巡墙器，它按格子推进，对完美迷宫一定能走到终点。你只要在常驻程序里新建一个 WallFollower，加一个 auto 开关，自动模式下用它的 decide 算出命令；再在网页上加个按钮切换自动和手动就行。机器狗大约九十秒、小乌龟大约十三秒就能自动通关。这两份巡墙器是参考实现，你的任务是理解它、接好它，再去做改进，比如改成左手法则，或者用广度优先搜索直接算最短路径。 |
| 21 | 智能Agent | 这里再补充一种被认可的完成方式：除了人工遥控、和自己写算法，你也可以接入一个智能体，比如 OpenClaw 这类大模型 Agent，让 AI 自己来开机器人。几个提示要点：第一，接口不变，Agent 只是换了发命令的大脑，仍然走和网页一样的命令接口，单一常驻程序原则照样适用；第二，做成感知决策执行的闭环，每个周期把位置、是否撞墙、是否到终点、迷宫地图整理好喂给它，让它只输出一个动作；第三，把动作空间限制死，只允许前进后退左转右转和停止，并在程序里做安全校验，撞墙就忽略前进，避免幻觉指令；第四，因为大模型有延迟和费用，建议降低决策频率，或者让 Agent 做高层规划、本地代码做低层执行，并在超时失败时回退到右手法则。用 Agent 自动通关，同样算自动探索达标。 |
| 22 | 报告书页数 | 再说说小组报告书怎么写。按人数定页数：一个人写两到三页，两个人四到五页，三个人六页左右，四人以上大约八页，平均每人两页。分工和每个人的具体贡献，必须写清楚。 |
| 23 | 报告书结构 | 报告书建议按这几节写：封面和项目概述、系统链路和迷宫设计、代码改动说明、自动探索策略和问题解决、最后是成果与分工。三人以上的机器狗组，分工要写明谁负责网络网页、谁负责迷宫碰撞、谁负责自动探索。 |
| 24 | 评分维度 | 评分维度供大家参考：链路打通占三成，迷宫探索占两成五，进阶功能占两成五，工程规范占一成，报告与展示占一成。所以，把链路打通和基本探索做扎实，再做一点自动探索和成果展示，分数就很可观了。 |
| 25 | 小结 | 最后小结一下。这一周，我们把网页、局域网、仿真、机器人串成了一条完整的手机遥控链路。核心原则是：网络接收和机器人控制，写在同一个常驻程序里。人多做机器狗、人少做小乌龟、单人也行。跑通之后，重点放在改地图、写自动探索、碰撞处理和成果展示。当你能用自己的手机，在迷宫里把机器人开起来，这门课的网络、环境、仿真、控制，就全部打通了。我们下次课见。 |
